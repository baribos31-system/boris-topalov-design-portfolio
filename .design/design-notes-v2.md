# Дизайн-система v2 — «Molten horizon»

Пересборка визуального языка портфолио по референсам заказчика. Предыдущая версия
(светлый минимализм, serif-заголовки) описана в `design-notes.md` и больше не действует.
Файлы: `assets/css/tokens.css`, `assets/css/components.css`, `assets/img/grain.svg`,
`assets/img/glow.svg`. HTML и `base.css` живут в параллельной ветке работы — контракт
разметки ниже обязателен для вёрстки.

---

## 1. Архетип поверхности

**Decide / Learn** — и главная, и страница кейса. Посетитель решает, звонить ли дизайнеру:
один тезис в hero → доказательства (кейсы) → контакт. Hero здесь уместен (единственная
поверхность, где он оправдан), но композиция не центрированная: заголовок, лид и действия
выровнены по левому краю, ритм держат масштаб и свечение, а не декор.

**Гибрид по брифу.** Бренд живёт в двух тёмных полосах — hero и финальный CTA-блок
(чёрный + оранжевая полусфера-глоу + зерно). Доказательства — светлые секции кейсов
(#F9F9F9, тёплый off-white), чтобы скриншоты и текст читались как материал, а не как реклама.
Тёмное = голос бренда, светлое = рабочая поверхность. Разделение постоянное в обеих темах:
оно не переключается, поэтому страница не «прыгает» при смене темы.

## 2. Что взято из референсов и почему

| Приём из референсов | Как реализован | Зачем |
|---|---|---|
| Зернистые градиентные меши (чёрный → красный → оранжевый → песочный) | `--grad-1…--grad-4` + тайл `grain.svg` поверх (blend `overlay`, opacity .14) | Убирает «цифровую» гладкость градиента: без зерна плавный градиент выглядит как дефолтный CSS, с зерном — как печатная плашка |
| Оранжевое свечение-полусфера из-под горизонта | `.hero__glow` / `.hero::before` / `.case-hero::before`: эллипс `border-radius: 50% 50% 0 0`, радиальный градиент, `blur(26px)`, `inset`-подсветка по кромке | Главный опознавательный знак стиля. Одна световая масса вместо десятка декоративных элементов; держит взгляд в центре композиции |
| ОГРОМНЫЕ заголовки капсом в плотном гротеске | `--fs-display: clamp(44px, 7.2vw, 104px)`, `line-height .9`, `letter-spacing -.045em`, uppercase | Типографика как главный носитель иерархии: на мобильном 44px уже плотно, на десктопе 104px — плакатно |
| Мелкие капс-лейблы с широкой разрядкой | `.eyebrow` / `.label`: 12px, `letter-spacing .16em`, оранжевая точка-маркер с glow | Второй голос системы; контраст «огромное / крошечное» вместо промежуточных кеглей |
| Стеклянные карточки с blur | `.request-card` (тёмное стекло), `.site-header` (glass, blur 20px) | Стекло применено только там, где есть реальная глубина позади: свечение и градиент под шапкой, глоу внутри карточки NDA |
| Тонкие линейные иконки | `stroke-width: 1.6`, `currentColor`, 17px в `.theme-toggle` | Иконки только функциональные (переключатель темы), без иконочных «фич-плиток» |
| Закруглённые карточки 20–24px | `--radius: 24px`, изображения внутри — `calc(--radius - 10px)` | Крупный радиус держит «мягкий» характер, вложенный радиус сохраняет параллельность кромок |

Осознанно **не** взято: цветной левый рейл на карточках, иконки над каждым заголовком,
гигантские цифры-метрики, центрированные секции, несколько акцентов сразу.

**Шапка и её собственный фон.** Прозрачность шапки — часть контракта читаемости:
посетитель скроллит чёрный hero, оранжевое свечение и белые секции кейсов под одной и той же
полосой, поэтому фон шапки задан почти непрозрачным (`--header-bg`) и не зависит от того,
что под ней. Коэффициенты посчитаны через композит alpha-over-backdrop (худший случай для каждой
темы), а не по «сырому» цвету токена.

| Пара | Композит фона шапки | Коэффициент | Порог |
|---|---|---|---|
| dark: `.nav a` `#A7A7A7` над светлой секцией `#F9F9F9` | **rgb(20,20,20)** | **7.66:1** | 4.5 |
| dark: `.logo` `#FFFFFF` там же | rgb(20,20,20) | **18.42:1** | 4.5 |
| dark: `.nav a` над hero `#000` | rgb(0,0,0) | **8.73:1** | 4.5 |
| light: `.nav a` `#4A4A4A` над hero `#000` | **rgb(237,237,237)** | **7.57:1** | 4.5 |
| light: `.logo` `#0A0A0A` там же | rgb(237,237,237) | **16.91:1** | 4.5 |
| light: `.nav a` над светлой секцией | rgb(249,249,249) | **8.42:1** | 4.5 |
| `.request-card .label` `#FF8A3D` на своей оранжевой плашке | rgb(54,41,32) | **5.99:1** | 4.5 |
| `.request-card p` `#A7A7A7` на теле карточки | rgb(29,28,26) | **7.08:1** | 4.5 |

До правки: тёмная шапка `rgba(10,9,8,.62)` над `#F9F9F9` давала композит **rgb(101,100,100)**,
и `.nav a` падал до **2.45:1**; светлая `rgba(249,249,249,.74)` над тёмным hero — до **2.98:1**.
Оба случая — регресс, который не видно при чтении токенов: контраст зависел от контента под полосой.

**Правила, вытекающие из цифр:**

1. **`#E85002` никогда не несёт белый мелкий текст** (3.76:1). Текст на оранжевом — только
   тёмный `--on-accent` (5.58:1). Это же решение визуально «свежее»: оранжевая кнопка
   с чёрной надписью, а не с белой.
2. **`#A7A7A7` нельзя использовать на светлом** (2.28:1 на `#F9F9F9`) — поэтому в светлом
   скоупе `--muted` переопределяется на `#646464`.
3. Оранжевый как цвет **текста** на светлом — только `#C10801` (`--accent-ink`), не `#E85002`.
4. Градиентный ховер primary-кнопки остаётся в яркой части (`#F16001 → #E85002 → #D9C3AB`),
   чтобы тёмная надпись не проваливалась: минимум по строке — 5.2:1.
5. **Шапка не наследует прозрачность страницы.** Любая «стеклянная» поверхность с alpha ниже
   ~.85 читаема только над своим обычным фоном; шапка же проезжает над контрастными полосами.
   Поэтому `--header-bg` = `.92` (dark) / `.95` (light): при смене секций под полосой
   коэффициент меняется на доли, а не втрое. Методика проверки — §10.
6. Текст на **тинтованной** плашке нельзя мерить по цвету плашки-«родителя»: `.request-card .label`
   лежит на `rgba(241,96,1,.08)` поверх тёмного стекла, и `#F16001` там даёт 4.26:1.
   Для мелкого капса на тёплой подложке — `#FF8A3D`.

## 4. Типографическая шкала

Serif удалён полностью. Один плотный гротеск на всё; иерархию держат кегль, вес и трекинг.

| Token | Значение | Роль | Line-height | Tracking |
|---|---|---|---|---|
| `--fs-display` | `clamp(44px, 7.2vw, 104px)` | `.hero__title`, h1 главной | .9 | -.045em |
| `--fs-hero` | `clamp(34px, 5.4vw, 84px)` | h1 без класса `.hero__title` | 1.0 | -.04em |
| `--fs-h2` | `clamp(26px, 4.2vw, 56px)` | заголовки секций, CTA | .96–.98 | -.035em |
| `--fs-h3` | `clamp(19px, 1.5vw, 24px)` | карточки, шаги | 1.12 | -.02em |
| `--fs-body` | `17px` | тело | 1.6 | 0 |
| `--fs-small` | `14px` | подписи, мета | 1.5 | 0 |
| `--fs-label` | `12px` | капс-лейблы | 1.2 | +.16em |

- Заголовки — `text-transform: uppercase`, вес 800. Капс только для display/h2/h3 и лейблов;
  тело, проза кейса и списки — обычный регистр (длинный русский текст капсом не читается).
- Кнопки и навигация — капс 11–12px, вес 700–800, трекинг .1em: это «третий голос»,
  который связывает шапку, кнопки и лейблы.
- `--font-display` и `--font-sans` — один и тот же стек: `Manrope → Inter Tight → Helvetica Neue
  → Segoe UI → Arial`. Когда локальный woff2 зарегистрируют через `@font-face`, менять нужно
  **только первое значение** обоих токенов. `base.css` должен объявить `@font-face`
  с `font-family: "Manrope"` (или заменить имя в токенах), `font-display: swap`,
  `font-weight: 400 800` для variable-файла.
- Ограничения ширины: hero-заголовок `19ch`, h1 кейса `17ch`, h2 `16–18ch`, лид `54–58ch`,
  проза `66ch` — русские длинные слова не рвут сетку.
- `text-wrap: balance` на заголовках, `pretty` на лиде; `overflow-wrap: break-word` на h1.

## 5. Анатомия компонентов

**Header** (`.site-header`). Sticky, стекло: `backdrop-filter: blur(20px) saturate(150%)`,
фон `--header-bg` — `rgba(0,0,0,.92)` в тёмной теме и `rgba(249,249,249,.95)` в светлой
(старые `.62` / `.74` не проходили контраст над светлыми секциями, §3), нижняя линия 1px
`--header-border`, высота `--header-h` 72px
(64px ≤860px). Логотип — капс 14px/800, трекинг .1em, оранжевый квадрат 8px с glow.
Навигация — капс 11–12px, `--header-ink` → `--header-ink-hover`, подчёркивание `scaleX 0→1`. Справа:
`.theme-toggle` (40×40 pill, иконка 17px, `stroke-width 1.6`), `.lang-toggle` (pill 40px),
`.header-cta` (компактная оранжевая pill 40px, всегда видна). ≤860px шапка в две строки:
логотип + контролы, ниже — навигация с горизонтальным скроллом без полосы.

**Hero** (`.hero` / `.hero--dark`). Тёмная сцена в обеих темах: `#000` + `--grad-4`
(тёплый меш слева сверху). `.hero__glow` — полусфера: ширина `min(1340px, 150vw)`,
`aspect-ratio 2.4/1`, `bottom: -2%`, `z-index: -1`, два радиальных слоя — горячее ядро
(`20% × 42%`, `rgba(255,214,176,.95) → #F16001 → 0`) и широкое тело купола
(`62% × 100%`, `#F16001 .92 → .55 → #C10801 .22 → 0` к 56%), `blur(26px)`, кромка
`inset 0 2px 0 rgba(255,214,180,.45)`.
Если разметки без `.hero__glow`, купол рисуется на `.hero::before` (тот же рецепт);
при наличии элемента псевдоэлемент отключается через `:has()`.
Зерно — `.hero::after`, `z-index 0`, opacity .14, `mix-blend-mode: overlay`, поверх глоу
и под текстом.
Нижний padding hero — `clamp(112px, 13vw, 200px)`: это «полоса горизонта», куда уходит
свечение. Проверено замером пикселей (контент скрыт, скриншот): под лидом и CTA фон
`rgb(4–49, 0–4, 0)`, контраст `--muted` 7.6–8.7:1; максимум свечения на кромке
`rgb(225,116,34)`. То есть глоу не съедает контраст мелкого текста.
`.hero__title` — uppercase, 800, `--fs-display`, line-height .9, tracking -.045em, max 19ch
(на 1440px заголовок на 3–4 строки, hero ~910px — кнопки остаются в первом экране).
`.hero__meta` — строка доверия капсом 12px: `display: flex; flex-wrap: wrap; gap: 6px 12px`,
`max-width: none` (иначе общий `p { max-width: 68ch }` из base.css режет строку до ~524px и она
переносится уже на десктопе). Разделители — отдельные `span.hero__meta-sep aria-hidden`, а не
псевдоэлементы: ≤720px они гасятся (`display: none`), остаётся увеличенный `column-gap: 16px`,
поэтому точка не повисает ни в конце, ни в начале перенесённой строки. Легаси-разметка без
`span`-разделителей поддерживается псевдоэлементом `> * + *::before`; при наличии
`.hero__meta-sep` он выключается через `:has()`, чтобы точка не удваивалась.
Кнопки — `.hero__actions`, gap 12px; ≤420px столбец на всю ширину.

**Buttons.** `.btn` — pill, высота 48px (46px ≤640px), капс 12px/800, tracking .1em.
Primary: заливка `#E85002 → #F16001`, текст `--on-accent`, тень `0 10px 30px -14px` оранжевая;
hover — «расплавленный» градиент `#F16001 → #E85002 → #D9C3AB` + `--shadow-glow` + подъём 2px.
Ghost: прозрачный, граница `--line-strong`, hover — `--accent-soft` + оранжевая граница.
Focus-visible — контур 2px `--accent`, offset 3px (виден и на тёмном, и на светлом).

**Sections.** `.section` — тёмный канвас, `clamp(56px, 8vw, 112px)` по вертикали.
`.section--light` — светлая панель внутри тёмного сайта: `#F9F9F9`, radius 24px,
локально переопределяет `--bg/--surface/--text/--muted/--line` и `--accent-ink: #C10801`.
Тот же скоуп работает у `.case-block` на страницах кейсов — поэтому компоненты внутри
(теги, шаги, галерея) автоматически переключаются в светлый регистр без отдельных селекторов.

**Case-card.** Белая карточка на светлой секции: padding 10px, изображение с внутренним radius,
заголовок 19–23px/800, описание `#4A4A4A` 15px, мета — капс 11px
внизу (`margin-top: auto`). Hover/focus: подъём 4px, оранжевая граница `.55`, оранжевое
свечение `0 26px 50px -26px` + внутренний контур 1px. Сетка асимметричная:
`1.16fr 1fr`, третий элемент — на всю ширину (широкий кейс или `.request-card`).
Медиа-блок первых двух карточек — **фиксированной высоты** `clamp(196px, 20vw, 292px)` при
`object-fit: cover` и `object-position: 50% 0`. Пропорция, выведенная из ширины, в несимметричной
сетке даёт разную высоту обложек (322px против 276px на 1440px) и разводит заголовки на 46px.
Проверка: `offsetTop` обоих `h3` совпадает (0px на 1440 / 1100 / 961 / 960 / 861 / 760 / 390px).
≤960px колонки равные → возвращается `aspect-ratio: 16/10`; ≤860px карточки в одну колонку →
`16/9` и `height: auto`.

**Request-card.** Тёмное стекло вместо карточки-заглушки: `blur(22px)`, тёплый радиальный
отблеск справа сверху, зерно, бордер `rgba(255,255,255,.14)`, радиус 24px, padding 24–44px,
заголовок uppercase 24–40px, текст `#A7A7A7`. Лейбл внутри (`.label`) — chip с рамкой
`rgba(241,96,1,.45)` и текстом `#FF8A3D` (мелкий капс на тинтованной плашке: `#F16001` давал
4.26:1, см. §3). Всегда на всю ширину сетки.

**Label / eyebrow.** `.label` — chip: рамка и padding приходят из `base.css`, компонентный
слой задаёт 11px/700, tracking .14em, цвет `--accent-ink` и `justify-self: start` (в grid
не растягивается). `.eyebrow` — маркер: оранжевая точка 6px со свечением + капс 12px
с tracking .16em; именно он живёт в hero, а не chip.

**Case-hero + case-meta.** Тёмный hero кейса (тот же глоу, `max 16ch`). Мета — три колонки
`dl/dt/dd` через вертикальные линии: подпись 10px капс `#8A8A8A`, значение 14px/600 белым;
≤640px — сетка 2 колонки без линий.

**Case-block.** Светлые читальные блоки `#F9F9F9`, между ними линия `#E6E2DC`. h2 — капс
22–40px/800. Проза `#333`, max 66ch. Ссылки подчёркнуты оранжевым (`.5`), hover — `#C10801`.

**Gallery.** 2 колонки → 1 ≤640px, изображения 1px бордер + radius 20 + мягкая тень,
подписи 13px `#646464`.

**Steps.** Счётчик `01…` капсом 12px/800 цветом `#C10801`, колонка 3.25rem, строки через
линию, описание `#4A4A4A`.

**Tags.** Оранжевые пилюли: фон `rgba(232,80,2,.08)`, граница `.32`, текст `--accent-ink`,

## 6. Темы

- Переключение: `<html data-theme="dark|light">`. **Dark — по умолчанию.**
- `tokens.css`: `:root` + `[data-theme="light"]` — светлые значения; `[data-theme="dark"]`
  и `html:not([data-theme])` — тёмные. Поэтому до выполнения скрипта (и при выключенном JS)
  сайт уже тёмный: нет вспышки белого.
- `color-scheme` переключается вместе с темой — системные скроллбары и формы не выпадают.
- Тёмный hero, CTA-band и footer остаются тёмными в обеих темах; светлые секции остаются
  светлыми. Меняются только фон страницы, шапка, `.section` и служебные поверхности.
- `.theme-toggle` поддерживает двухзначковую схему: `[data-theme-icon="sun"]` видна в тёмной
  теме, `[data-theme-icon="moon"]` — в светлой. Одна иконка тоже работает.
- `localStorage` и `prefers-color-scheme` — зона `main.js`; CSS от них не зависит.

## 8. Доступность и адаптив

- Тач-цели: кнопки 46–48px, контролы шапки 40px (38px ≤420px), навигация — padding 6–8px.
- `:focus-visible` — контур 2px `--accent` с offset 3px на всех интерактивных элементах,
  включая карточки-ссылки и переключатели.
- `prefers-reduced-motion: reduce` — отключаются все transitions, hover-подъёмы и smooth scroll.
  Свечение статично (анимаций нет вообще, кроме hover-переходов), поэтому «мерцания» нет.
- Горизонтальный скролл: все сетки на `minmax(0, 1fr)`, глоу обрезается `overflow: clip`,
  навигация на мобильном скроллится внутри себя; проверено 360 / 390 / 768 / 1024 / 1440.
- Тёмная тема — не инверсия: в ней `--muted #A7A7A7` (8.73:1), а в светлой `#646464` (5.62:1).
  Один и тот же серый в двух темах дал бы провал в одной из них.
- Стекло шапки имеет `@supports`-фолбэк на непрозрачный фон, а её фон почти непрозрачен
  (`--header-bg`), поэтому навигация читается над любой секцией под полосой (7.57–8.73:1, §3).
- Мелкий текст на светлых секциях тёмной темы остаётся в светлом скоупе (`--muted #646464`,
  тело карточки `#4A4A4A`, акцент `#C10801`): 5.6–8.9:1. Шапка — единственная поверхность,
  которая не наследует скоуп секции, поэтому у неё собственные токены.
- `p { max-width: 68ch }` из base.css действует на все абзацы, включая `.hero__meta`;
  компонент сбрасывает его (`max-width: none`) там, где строка должна жить в одну линию.
- Зерно и глоу — `pointer-events: none` и декоративные (`aria-hidden` на `.hero__glow`).

## 9. Slop self-audit (claude-design, 10 признаков)

Аудит проведён дважды: по «наивной» реализации брифа (первый черновик нового стиля) и по
итоговой системе. Диагноз — до правок, лечение — только по тем признакам, что сработали.

**До правок — 5/10.** Сработали признаки 1, 3, 5, 8, 9.

| # | Признак | До | После |
|---|---|---|---|

систему не нужно пересобирать, только поддерживать.

## 10. Регрессии ревью v2.1 (три дефекта из браузера)

Правки только в `assets/css/components.css`, `assets/css/tokens.css`, этом файле. HTML/JS
и `base.css` не тронуты.

### 10.1 Шапка над светлыми секциями (критично)

- **Симптом.** В тёмной теме при скролле до `.section--light` шапка превращалась в серую
  полупрозрачную полосу: `.nav a` — серый на сером.
- **Причина.** `background: var(--glass-bg)` = `rgba(10,9,8,.62)` + `backdrop-filter`:
  контраст зависел от контента **под** полосой. Композит над `#F9F9F9` = `rgb(101,100,100)`,
  `#A7A7A7` на нём — **2.45:1**. В светлой теме та же ошибка зеркально: `.74` над чёрным hero
  давала `rgb(184,184,184)` и `#646464` — **2.98:1**.
- **Решение.** Токены `--header-bg` / `--header-border` / `--header-ink` / `--header-ink-hover`
  в обеих темах; alpha `.92` (dark) и `.95` (light). Blur остался, но он больше не влияет
  на читаемость. Затронуты селекторы: `.site-header`, `.logo`, `.nav a` (в т.ч. `:hover`,
  `:focus-visible`, `[aria-current]`), `.theme-toggle`, `.lang-toggle`, `.lang-toggle a`.
- **Замер.** Тёмная тема, скролл 1250px (шапка целиком над белой секцией), `backdrop-filter`
  временно отключён, чтобы прочитать честный alpha-композит: фон шапки = **rgb(20,20,20)**,
  `.nav a` = **7.66:1**, `.logo` = **18.42:1**. Светлая тема, шапка над hero:
  фон **rgb(236,236,236)**, `.nav a` = **7.57:1**, `.logo` = **16.91:1**.

### 10.2 Карточки кейсов в сетке

- **Симптом.** У первой карточки обложка выше, у второй ниже; заголовки и мета-строки
  на разной высоте, карточки выглядят рвано.
- **Причина.** `.case-card img { aspect-ratio: 16/9 }` выводит высоту из **ширины**, а колонки
  сетки неравные (`1.16fr` / `1fr`): 322px против 276px на 1440px, заголовки разъехались на 46px.
- **Решение.** Медиа-блок первых двух карточек — фиксированная высота `clamp(196px, 20vw, 292px)`,
  `aspect-ratio: auto`, `object-fit: cover`, `object-position: 50% 0` (дашборд — портретный
  экспорт 1440×1680, сверху видно обзорную панель). `display: block` + `flex: 0 0 auto`
  в колонке-флексе карточки. ≤960px (равные колонки) — `16/10` с `height: auto`,
  ≤860px (одна колонка) — `16/9`. Hover-состояние не менялось.
- **Замер.** `h3` offsetTop в документе: 1558.81 / 1558.81 (Δ = 0) на 1440px; Δ = 0 также
  на 1100 / 961 / 960 / 900 / 861 / 860 / 760 / 721 / 720 / 390px. Высота медиа равна
  (288 / 288 на 1440px), высота карточек равна (451.25 / 451.25).

### 10.3 `.hero__meta` висячий разделитель

- **Симптом.** «8 ЛЕТ · SENIOR PRODUCT DESIGNER · МАРКЕТПЛЕЙСЫ…» переносится, точка-разделитель
  оказывается в начале/конце строки.
- **Причина.** Две сразу: (1) разделитель рисовался `> * + *::before` **внутри** элемента,
  поэтому он уезжал вместе с ним на новую строку; (2) общий `p { max-width: 68ch }` из base.css
  резал строку до ~524px при доступных 1132px — перенос случался уже на десктопе.
- **Решение.** `max-width: none`; `display: flex; flex-wrap: wrap; gap: 6px 12px`;
  реальные `span.hero__meta-sep` стилизованы (`flex: none`, `line-height: inherit` — точка
  стоит на базовой линии капса); легаси-псевдоэлемент гасится через `:has(.hero__meta-sep)`,
  чтобы точка не удваивалась; ≤720px разделители скрываются, остаётся `column-gap: 16px`.
  Uppercase и `letter-spacing: .14em` не тронуты.
- **Замер.** 1440px: строка одна (высота 19.19px), все пять детей имеют одинаковый `top`
  (545.94), точки видны (ширина 6px каждая). 720px и ниже: `display: none`, строка живёт
  на увеличенном gap; 390px — 3 строки без разделителей.

### Как перепроверить

Скрипт ниже (python 3, из корня проекта) проверяет и синтаксис, и alpha, и контраст.
Он запускался на этих файлах; вывод приведён в §10.1.

```python
import re, pathlib

root = pathlib.Path("assets/css")
comp = (root / "components.css").read_text(encoding="utf-8")
toks = (root / "tokens.css").read_text(encoding="utf-8")

# 0) баланс скобок (комментарии и строки замаскированы)
for name in ("tokens.css", "components.css"):
    src = (root / name).read_text(encoding="utf-8")
    src = re.sub(r"/\*.*?\*/", "", src, flags=re.S)
    src = re.sub(r'"(?:\\.[^"\\]|[^"\\])*"', '""', src)
    assert src.count("{") == src.count("}"), name
    assert src.count("(") == src.count(")"), name

# комментарии содержат примеры селекторов — иначе regex попадёт в шапку файла
toks = re.sub(r"/\*.*?\*/", "", toks, flags=re.S)

# 1) шапка берёт фон из токена, а не из старого --glass-bg
assert re.search(r"\.site-header\s*\{[^}]*background:\s*var\(--header-bg\)", comp, re.S)

def lin(c):
    c /= 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def L(rgb):
    r, g, b = rgb
    return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)

def ratio(a, b):
    la, lb = L(a), L(b)
    return (max(la, lb) + .05) / (min(la, lb) + .05)

def scope_block(pattern):
    return re.search(pattern + r"[^{]*\{([^}]*)\}", toks, re.S).group(1)

def token(block, name):
    return re.search(r"--" + name + r":\s*([^;]+);", block).group(1).strip()

def rgb_alpha(value):
    r, g, b, a = re.match(r"rgba?\(\s*(\d+)\s*,\s*(\d+)\s*,\s*(\d+)\s*,?\s*([\d.]*)\s*\)", value).groups()
    return (int(r), int(g), int(b)), float(a or 1)

def hex_rgb(value):
    v = value.lstrip("#")
    return tuple(int(v[i:i + 2], 16) for i in (0, 2, 4))

PANEL, HERO = (249, 249, 249), (0, 0, 0)
for label, scope in (("dark", r'\[data-theme="dark"\]'), ("light", r'\[data-theme="light"\]')):
    block = scope_block(scope)
    raw, a = rgb_alpha(token(block, "header-bg"))
    assert a >= 0.85, (label, a)            # <-- требование к шапке
    print(f"{label}: --header-bg {token(block, 'header-bg')}  alpha={a}")
    for name, backdrop in (("light panel", PANEL), ("hero", HERO)):
        c = tuple(round(a * f + (1 - a) * b) for f, b in zip(raw, backdrop))
        print(f"   over {name:12} rgb{c}  nav {ratio(hex_rgb(token(block, 'header-ink')), c):.2f}:1"
              f"  logo {ratio(hex_rgb(token(block, 'header-ink-hover')), c):.2f}:1")
print("OK: alpha >= 0.85 in both themes")
```

Ожидаемый вывод (совпадает с текущим деревом):

```

   over light panel  rgb(20, 20, 20)  nav 7.66:1  logo 18.42:1
   over hero         rgb(0, 0, 0)  nav 8.73:1  logo 21.00:1
light: --header-bg rgba(249, 249, 249, .95)  alpha=0.95
   over light panel  rgb(249, 249, 249)  nav 8.42:1  logo 18.80:1
   over hero         rgb(237, 237, 237)  nav 7.57:1  logo 16.91:1
OK: alpha >= 0.85 in both themes
```

В браузере честный композит шапки читается только при `backdrop-filter: none` (иначе движок
подмешивает размытый фон): временно отключить фильтр, проскроллить к `.section--light`,
снять скриншот и взять пиксель внутри полосы. Ожидаемо `rgb(20,20,20)` в тёмной теме
и `rgb(236,236,236)` в светлой над hero.
